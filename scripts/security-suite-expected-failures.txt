# Known gaps
# ----------
# Asserted here, but narrower than the finding they come from. Closing the
# pinned property does not close the whole finding:
#
#   facade upgrade path  — hop-by-hop header forwarding and the absent splice
#                          read deadlines are not asserted
#   snapshot integrity   — the argv-from-workdir defect is asserted for the
#                          live-reload spawn site (via a symlink-into-
#                          node_modules fixture that keeps the bundle hash
#                          unaffected) and, independently, at the pure
#                          BundleHash/LoadMeta level in internal/config. The
#                          serve and cold-start spawn sites are NOT asserted:
#                          serve's supervisor is nil in the test harness, and
#                          cold-start (start.go) builds its supervisor inline
#                          with the real authorizer and no injection point —
#                          both need the snapshot-only-spec refactor (or an
#                          equivalent seam) before they are unit-testable
#   control plane auth   — three of twelve routes are asserted (start-mode
#                          reload and activate, serve-mode activate); serve's
#                          deactivate/dirs/reload-global/session and start's
#                          dirs/deactivate/reload-global/session are not
#   metadata deny        — the direct path's resolved-address screen for
#                          non-link-local metadata (Oracle's 192.0.0.192) and
#                          the chained proxy's subdomain-of-hard-deny case are
#                          not asserted
#   binary resolution     — only the "/" root-grant case is asserted; the
#                          symlink-hop and install-prefix variants (#48) are not
#   tool cache             — only the default scope; the cache stays a persistent
#                          host directory granted read-write to the sandbox
#   kernel/tiocsti gate    — no launch-time check of dev.tty.legacy_tiocsti or
#                          a numeric kernel-version comparison exists to test;
#                          this is new functionality, not covered
#
# Duplicated logic no test covers: internal/cli/provenance.go:94 keeps its own
# copy of the metadata deny list, and internal/cli/diagnose_probe.go:89 its own
# weaker isLoopbackHost. Fixing internal/netproxy leaves both reporting the old
# verdict to the user.
#
# Deliberately not covered: the self-update signing finding. Prior adversarial
# validation rejected it — goreleaser-default same-origin checksums are the
# design, not a defect — so a red test would demand a fix nobody intends. The
# narrower `apk add --allow-untrusted` in internal/updater/pkgmanagers.go:34
# was not part of that judgement and is simply untested.
#
# CI / supply-chain findings — partially covered.
